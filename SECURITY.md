# Security Policy

This document describes the security policy for this repository, including the types of issues considered security
vulnerabilities and the process for reporting them.

## Reporting a Vulnerability

**DO NOT open a public issue, merge request, or discussion for security vulnerabilities.**
Publicly disclosing a vulnerability makes it easier for malicious attackers to exploit it before a fix is released.

---

## How to Report

Please report security vulnerabilities using one of the following methods:

1. **Email (Preferred):** Send an email to `security@qboard.tech`.
2. **GitLab Confidential Issue** (requires an account on this GitLab instance):
   - Go to the "Issues" tab of this repository, click **New issue.**
   - Check the box labeled **This issue is confidential**.
   - Click the **Create issue** button at the bottom.

---

## What information to provide:

* A detailed description of the vulnerability.
* Clear, step-by-step instructions to reproduce the issue (or a Proof of Concept script).
* Screenshots, logs, or video recordings (screencasts) that visually demonstrate the vulnerability process.

---

## Our Response Process

After receiving your report, we will:

1. Acknowledge receipt of your report within **72 hours**.
2. Work on a fix in a private branch or repository.
3. Coordinate a release date for the security patch.
4. Provide credit to you (the reporter) in our release notes.

---

## Disclosure Policy

We follow a coordinated disclosure model. We ask that you do not disclose the vulnerability to the public or
any third party until we have released a fix and updated our users. This ensures the safety of everyone using this software.
